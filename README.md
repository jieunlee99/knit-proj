# Knit Project

보유한 뜨개실의 재고와 진행 중인 뜨개 프로젝트를 한곳에서 관리하는 개인용 웹 서비스입니다.

실의 상품 정보와 색상·로트별 재고를 분리하여 관리하고, 보유 무게를 기준으로 남은 길이를 계산합니다. 프로젝트별 예상 소요량과 실제 사용량을 기록하여 어떤 실을 얼마나 가지고 있고 어디에 사용했는지 확인할 수 있도록 만드는 것이 목표입니다.

## 프로젝트를 시작한 이유

뜨개질을 하면서 같은 상품이라도 색상과 로트가 다른 실을 구분하고, 남은 실의 양과 프로젝트별 사용량을 기록할 필요가 있었습니다. 이 과정을 단순 메모가 아닌 재고 관리 도메인으로 구현하면서 Spring 기반 백엔드 설계, 데이터 정합성, 테스트 및 배포 경험을 쌓기 위해 시작했습니다.

## 핵심 기능

### 실 상품 관리

- 제조사, 상품명, 성분 등록
- 실 상품의 100g당 길이 등록
- 권장 바늘 크기 등 상품 공통 정보 관리

### 실 재고 관리

- 상품별 색상과 로트 번호 관리
- 구매일과 구매 무게 기록
- 현재 보유 무게 관리
- 보유 무게를 길이로 환산하여 제공

### 뜨개 프로젝트 관리

- 프로젝트 상태와 진행 기간 관리
- 도안, 바늘 크기, 목표 및 실제 게이지 기록
- 프로젝트에 사용할 실과 예상 소요량 기록
- 실제 사용량 반영 및 실 재고 차감

## 핵심 도메인 규칙

상품에는 `100g당 길이(m)`를 저장하고, 재고에는 실제로 보유한 `무게(g)`를 저장합니다. 현재 보유 길이는 별도 데이터로 저장하지 않고 조회 시 계산합니다.

```text
보유 길이(m) = 보유 무게(g) * 100g당 길이(m) / 100
```

예를 들어 100g당 250m인 실을 180g 가지고 있다면 보유 길이는 450m입니다.

- 무게와 길이는 부동소수점 오차를 피하기 위해 `BigDecimal`로 처리합니다.
- 같은 상품이라도 색상이나 로트 번호가 다르면 별도 재고로 관리합니다.
- 실제 사용량은 현재 재고보다 클 수 없습니다.
- 사용량이 반영되면 해당 재고의 보유 무게가 감소합니다.
- 계산 가능한 길이 값은 중복 저장하지 않아 데이터 불일치를 방지합니다.

## MVP 범위

- [ ] 실 상품 등록·조회·수정·삭제
- [ ] 로트별 실 재고 등록·조회·수정·삭제
- [ ] 보유 무게 기반 길이 계산
- [ ] 뜨개 프로젝트 등록 및 상태 관리
- [ ] 프로젝트에 실 배정
- [ ] 실 사용량 기록 및 재고 차감
- [ ] 핵심 비즈니스 규칙 테스트

다음 항목은 MVP 완성 이후 필요성에 따라 추가합니다.

- 회원가입 및 로그인
- 도안과 완성 사진 파일 업로드
- 검색 및 페이징
- PostgreSQL 전환 및 배포
- CI/CD와 모니터링

## 개발 환경 실행

### 요구 사항

- Java 21

### 애플리케이션 실행

```bash
./gradlew bootRun
```

기본 접속 주소는 `http://localhost:8080`입니다.

### H2 Console

개발 서버가 실행된 상태에서 `http://localhost:8080/h2-console/`에 접속합니다.

```text
JDBC URL: jdbc:h2:mem:knit
User Name: sa
Password: 비워두기
```

인메모리 DB를 사용하므로 애플리케이션을 종료하면 개발 데이터가 초기화됩니다.

## 개발 원칙

- 기능 단위로 작게 구현하고 동작 가능한 상태를 유지합니다.
- 컨트롤러에 비즈니스 로직을 두지 않습니다.
- 엔티티를 API 요청·응답 객체로 직접 사용하지 않습니다.
- 재고 변경과 같이 정합성이 필요한 로직은 트랜잭션 안에서 처리합니다.
- 핵심 도메인 규칙은 테스트로 보호합니다.
- 구현되지 않은 기술을 사용 기술로 표기하지 않습니다.

## 진행 상태

현재 Spring Boot 프로젝트와 H2 기반 로컬 개발 환경을 구성한 상태입니다. 첫 번째 구현 대상은 실 상품 도메인과 등록·조회 기능입니다.
